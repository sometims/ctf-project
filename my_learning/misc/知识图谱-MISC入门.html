📚 二、8 大核心技术点

1️⃣ AES ZIP 加密（compression method 99）

工具pyzipper
from pyzipper import AESZipFile
with AESZipFile('f.zip','r') as zf:
    zf.setpassword(b'pwd')
    zf.extractall('out')

坑Windows 自带 unzip 命令不支持 method 99，会报"unsupported compression method 99"错误。

2️⃣ JPEG 尾部追加数据

工具010 Editor / hex

JPEG EOI 标记 = \xFF\xD9。EOI 之后的内容是"附加数据"，不属于 JPEG 本身。

FFD8FFE0... [JPEG 数据] ...FFD9 [附加数据]

3️⃣ crypto-js OpenSSL 兼容 AES

特征U2FsdGVkX1 (= Salted__)

crypto-js 默认使用 OpenSSL 的 EVP_BytesToKey(MD5, salt+password) 派生 key+iv，迭代生成 32+16 字节。

def evp_bytes_to_key(password, salt):
    d = md5(password + salt)
    d += md5(d + password + salt)
    return d[:32], d[32:48]

4️⃣ 盲水印（频域水印 FWT/SVD）

工具WaterMark、BlindWatermark

将水印信息嵌入到图片的频域系数中（傅里叶变换/奇异值分解），肉眼不可见但提取后能看到文字。

提示词"傅里叶"= 频域隐写。

5️⃣ LSB 隐写（cloacked-pixel）

工具cloacked-pixel (livz)

修改 PNG 像素 RGB 通道的最低位（bit 0）来存储数据，每像素藏 3 bit。

AESCipher = SHA-256(password) → AES-256-CBC
extract: 逐像素取 R&1,G&1,B&1 → 重组字节 → AES 解密

6️⃣ 中文电报码

规则4 位数字 = 1 汉字

7230=青 1421=少 1628=年 0226=们 6386=起 7378=飞

查询：https://dianma.bmcx.com/

7️⃣ 中文文件名 ZIP 密码

编码GBK（不是 UTF-8）

压缩包内文件名是 GBK 时，密码也用 GBK 编码（否则失败）。

zf.setpassword('密码'.encode('gbk'))

Python 错误模式：'utf-8' codec can't encode character → 改用 gbk。

8️⃣ 盲文（BrailIe）

UnicodeU+2800 ~ U+28FF

key.txt 末尾的 ⠟⠎⠝⠉⠞⠋⠼⠊⠊⠊⠊ = qsnCTF9999

查询：https://www.qqxiuzi.cn/bianma/wenbenjiami.php?s=mangwen

⚠️ 四、本题两个关键坑（必须避）

坑 1：cloacked-pixel 密码不是字典能爆出来的！密码 qsnctfNB666 来自 fla2_key.jpg 的盲水印——需要先做 WaterMark 提取。如果只字典爆破，永远找不到。
坑 2：Free File Camouflage 是 .NET GUI 工具，Python 复现困难。使用 RijndaelManaged + Rfc2898DeriveBytes（PBKDF2）+ 特定参数。Python 试了 50+ KDF 组合都失败。必须用 Windows GUI 工具直接解密。

🎓 五、MISC 入门核心方法论

  1. 先看 hint：通常给出密码、解题顺序、关键提示（如"傅里叶"=频域）
  2. 分层剥离：JPEG 看 EOI 后、PNG 看 tEXt 注释、ZIP 看文件结构
  3. 工具先识别文件类型：file 头（89504e47=PNG, ffd8ffe0=JPEG, 504b0304=ZIP）
  4. 密码来源常在图片里：盲水印、LSB、文件名暗示、谐音梗
  5. 中文密码记得 GBK：很多新手栽在 utf-8 vs gbk
  6. 遇到 .NET 工具直接用 GUI：不要死磕 Python 复现
  7. WP 是最好的老师：卡住时搜同题 WP 看完整链路

🔍 零宽字符隐写（Zero-Width Stego）

txt 文件开头藏 不可见字符（U+200B/C/D/E/F、U+FEFF）。本题用 5 种字符 = 5 进制 编码：

\u200e=0 \u200f=1 \u200c=2 \u200d=3 \ufeff=4
每组 3 字符 = 5进制数 → ASCII
\u200b = 分组分隔符
→ "Password is : Hanser2024"

坑不是所有零宽隐写都是 2 进制！先统计字符种类数，种类=k 就试 k 进制。

🖼 PSD 图层元数据挖 flag

Photoshop 文件的图层名/图层文本存在 XML 描述区，直接正则搜：

re.findall(rb'<photoshop:LayerName>([^<]+)</photoshop:LayerName>', data)
re.findall(rb'<photoshop:LayerText>([^<]+)</photoshop:LayerText>', data)

本题图层名 = FLAG，图层文本 = flag。

原理PSD 的 XMP/图层描述区是明文 XML，任何隐藏文字都能 strings/正则提取。

👻 零宽字符隐写（unicodeSteganographer）

肉眼是一片「我不想上早八」，真信息藏在不可见字符里。

  • 默认字符集 4 个：U+200C U+200D U+202C U+FEFF
  • radix=4 → 每 4 个零宽字符 = 1 字节
  • 解出的字节流是 UTF-16BE，不是 UTF-8
最大坑：漏检 U+202C 会让 radix 算成 3，整串全乱。检测要"全"，把 8 种常见零宽字符都列进去。
ZIP AES 复现：method=99 是 WinZip AES，标准 zipfile 不支持，必须用 pyzipper：z.read(name, pwd=b'密码')。

📏 IHDR 高度被改（最常见的 PNG 隐写）

改小高度 → 多出来的行不渲染，但 IDAT 里数据还在。

真实高度 = IDAT解压长度 ÷ (1 + 宽 × 每像素字节)
1148230 ÷ (1 + 721×4) = 398

改完 必须重算 CRC32，否则工具直接报错：

p[20:24] = struct.pack('>I', 398)
crc = zlib.crc32(bytes(p[12:29])) & 0xffffffff
p[29:33] = struct.pack('>I', crc)

🔢 996 不是装饰，是索引表

图里露出的「996」转二进制 = 1111100100，正好 6 个 1、4 个 0，与压缩包内 6 个「第X个1.txt」+ 4 个「第X个0.txt」数量对上。

位序位值取文件内容
11第一个1.txtLr
21第二个1.txtp5
31第三个1.txtmJ
41第四个1.txtcd
51第五个1.txtEb
60第一个0.txtbv2
70第二个0.txtbn
81第六个1.txtf6H
90第三个0.txtQS
100第四个0.txtNh
坑：0 和 1 的编号各自独立计数。第 6 位是整串第 1 个 0 → 取「第一个0.txt」，不是「第六个0.txt」。

🔤 HTML 实体编码

每个 txt 内容是 &#98;&#118;&#50;，即 ASCII 98/118/50 = bv2。

import html
html.unescape('bv2')  # 'bv2'

🧠 本题最大教训

曾把拼接串 bv2Lrbnp5QSmJNhcdEbf6H 当 Base64 解，穷举 10 个片段全部 3,628,800 种排列都解不出可读文本。
根因不是顺序，是压根不该 Base64 —— 拼完那串本身就是 flag 内文。
先想清楚「这串东西应该是什么」，再决定解码方式。

ZIP 辨析flags 有 0x0001 才是加密；0x0002 只是 deflate 压缩选项

📋 图片+压缩包组合题的固定检查顺序： ① 压缩包先看 flags（0x0001 才要密码）→ ② 图片找多个文件签名看有无串联 → ③ 打不开就核对 IHDR 宽高与 IDAT 长度 → ④ 能打开就先读图上的字 → ⑤ 一堆按数字/0-1 命名的小文件，找一个"数量刚好对上"的数转二进制当索引 → ⑥ 内容像 &#xx; 是 HTML 实体，像 \uXXXX 是 Unicode 转义。
