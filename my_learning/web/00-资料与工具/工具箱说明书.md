## 1. sensitive_scan.py —— 敏感文件扫描器

**什么时候用**：开局信息收集——不确定靶机藏了什么（备份/源码/配置/flag），扫一遍看有哪些敏感文件。

**用法**：
```bash
python sensitive_scan.py <网址>
python sensitive_scan.py http://challenge.qsnctf.com:xxxxx/
```

**它做什么**：
1. 爆破常见敏感路径（.git/.svn/.bak/robots/flag变体…）
2. 防假200（响应与首页相同则跳过，防刷屏）
3. 解析 robots.txt 并自动加入其 Disallow 路径
4. 下载可读文件，搜索 flag 特征（flag{ / n1book{ / ctfshow{ 等）

**输出**：`[状态码] 路径 → flag片段`

## 2. combine_scan.py —— 目录+敏感文件 二合一

**什么时候用**：先找目录（/backup/ /upload/ /admin），再往目录里挖敏感文件——两件事一次跑完。

**用法**：
```bash
python combine_scan.py <网址>
```

**它做什么**：
- 第1阶段：目录扫描（复用 mini_scanner 逻辑）→ 发现目录/文件
- 第2阶段：对每个发现的目录再跑敏感文件探测（复用 sensitive_scan 逻辑）→ 如 /backup/.git、/backup/.DS_Store

**依赖**：需要同目录下的 `mini_scanner.py` 和 `sensitive_scan.py`（自动 import）。

---

## 3. mini_scanner.py —— 迷你目录扫描器

**什么时候用**：只需要快速扫目录/文件，轻量、防假200。

**用法**：
```bash
python mini_scanner.py http://靶机/
```

**核心原理**：逐个请求常见路径，非 404 即存在；**先记录首页内容，响应与首页一样的标为【假200】自动忽略**（很多服务器对不存在的路径也返回 200 首页）。

## 4. git_search.py —— git 仓库自动搜 flag

**什么时候用**：发现 `.git` 泄露，用 git-dumper 下载仓库后，全库搜 flag（包括历史提交里删掉的）。

**用法**：
```bash
python git_search.py <git仓库目录>
```

**它做什么**：遍历所有 blob（当前文件 + 历史版本 + 悬空对象）逐个搜 flag 特征 + 检查提交说明 + 列出分支/reflog。

**输出**：找到的 flag 及其位置（文件路径/提交哈希/提交说明）。

---

## 5. swp_extract.py —— .swp 文件恢复

**什么时候用**：发现 `.index.php.swp` 之类的 Vim 交换文件（Vim yyds 题套路）。

**用法**：
```bash
python swp_extract.py 下载到的.swp文件
```

**原理**：.swp 是二进制交换文件，但被编辑的可见字符原样保留 → 提取可读字符串即可还原源码。

---

## 6. php_eval_chain.py —— PHP 变量链 eval 利用

**什么时候用**：遇到 `$$...$_` 多层变量链 eval 的题（CTF-Show 变量的变量 eval 套路）。

**用法**：
```bash
python php_eval_chain.py <host> <depth> <code> [scan]
# 示例：depth=0 + scan = 自动扫 1~45 层找正确层数（用 EVALOK 标记验证）
python php_eval_chain.py xxx.challenge.ctf.show 0 "system('cat /flag');" scan
python php_eval_chain.py xxx.challenge.ctf.show 36 "echo 'EVALOK';"
```

**它做什么**：自动构造 `_=a&a=b&b=c&...&z=code` 变量链并 POST，eval 执行 code。

## 通用提醒

- **Windows 用 `python`**，不是 `python3`
- 复杂 payload 一律写脚本文件发（PowerShell 引号地狱）
- 靶机会过期：地址和 flag 会变，做题抓紧
- 每个脚本头部 docstring 都有更详细的参数说明，说明书和 docstring 冲突时以实际运行输出为准（实测原则）
