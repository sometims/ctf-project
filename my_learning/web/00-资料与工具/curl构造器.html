十个必踩的坑

      生成命令后先对照一眼
    

    

      
01
PowerShell 里 curl 不是 curl
它是 Invoke-WebRequest 的别名，不认 -H/-d。写 curl.exe，或者用 Git Bash。

      
02
-s 会把错误一起吞掉
请求失败时终端一片空白，容易误判成靶机没响应。永远写 -sS。

      
03
-d 偷偷把方法变成 POST
想发 GET 带参数，用 -G --data-urlencode，或者直接拼进 URL。

      
04
& 是 shell 的特殊字符
-d "a=1&b=2" 必须加引号，否则 shell 把 & 当后台执行符，命令被切成两半。

      
05
不加 -L 只能看到 302
登录成功后跳转的题，不加 -L 会以为登录失败。

      
06
-d 会吃掉换行
发 JSON 用 --data-binary 或 --json，否则多行 JSON 变一行还丢缩进。

      
07
代理环境变量会劫持请求
返回 502 先怀疑代理。用 --noproxy '*' 强制直连，再用 -v 对比。

      
08
curl 会归一化 ../
路径穿越题一定要加 --path-as-is，否则 ../ 在发出去之前就被吃掉了。

      
09
URL 里的 [] 会被当通配
curl 默认把 {}/[] 当范围展开。含这些字符时加 --globoff。

      
10
-G 会把 POST body 搬空
它不是「POST 转 GET」的开关：所有 -d 数据会移到 URL 并改用 GET。想同时带查询参数和 POST body，别加 -G。
