# 🗂 Web 笔记 23｜Burp 密码爆破全流程（手把手）

> 场景：登录题拿不到密码 → 上 Burp Intruder 自动试字典
> 实战样本：qsnctf 40357（用户名 sqctf 已知，密码 1q2w3e4r 爆破命中）

---

## 一、什么时候用爆破

- 登录题卡密码，且**无验证码、无登录限速**（输错不锁）
- 用户名已知（或能猜：admin/sqctf/root...），只差密码
- SQL 注入试过无效（参数化查询/硬编码比对）

> 爆破本质：**字典 × 自动发请求 × 找「不一样的响应」**。先知道错误响应长啥样，再找响应变的那个密码。

## 三、Intruder 六步（核心流程）

```
① 抓登录请求 → 右键 → Send to Intruder
② Positions 标签 → 点 Clear（清掉自动标记）
③ 选中密码的值（如 123456）→ 点 Add（变成 §123456§ = 要替换的位置）
   ⚠️ 只标记密码！用户名别动（除非也要爆）
④ Payloads 标签 → Payload type: Simple list → 点 Load → 选字典文件
⑤ Settings 标签（可选）→ 线程 10~20（太快易触发风控）
⑥ 点右上角 Start attack
```

## 四、怎么认命中（重点：不用看页面）

### 第 1 步：点 Length 列头排序

```
爆破完 → 点 "Length" 列头 → 列表按长度排序
错误响应几乎都是同一个长度（如 4515B）
长度离群的那行（如 889B）= 响应变了 = 命中！
```

### 第 2 步：确认命中（三种方法）

| 方法 | 操作 |
|---|---|
| 下方 Response 面板 | 选中那行 → 下面 Response 标签直接看完整响应（页面变了 = 对） |
| Send to Repeater | 右键 → Send to Repeater → 再看一遍（还能改包重发） |
| Show response in browser | 右键 → 浏览器里看渲染效果 |

### 判断信号优先级

| 信号 | 怎么用 |
|---|---|
| **Length（最强）** | 排序后找离群行——错误响应长度一致，它不一样 |
| **Status** | 成功可能返回 302（跳转）/200（进下一关） |
| **Response 内容** | 错误提示（如「用户名或密码错误」）消失 = 对 |

> 命中后**人工复核**：用真密码手动登录一次，看到页面变化才确认。

## 五、常见坑

| 坑 | 后果 | 解法 |
|---|---|---|
| 标记了 username 位置 | 用户名也被替换，全错 | Clear 后只标记密码 |
| 字典有 CRLF（Windows 换行） | 密码带 \r 全错 | 字典用 Unix 换行（LF） |
| 线程开 999 | 被风控/封 IP | 10~20 稳妥 |
| 有验证码 | 爆破必然失败 | 换思路（SQL注入/源码） |
| 响应都一样长 | 长度信号失效 | 看 Status / Set-Cookie / 人工抽查 |
