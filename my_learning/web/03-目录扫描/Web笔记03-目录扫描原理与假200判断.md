# 🗂 Web 笔记 03｜目录扫描原理 & 假 200 判断

> 记录自：NSSCTF [LitCTF 2023] PHP是世界上最好的语言 ｜ 2026-08-01
> 核心认知：**网站能访问的（web目录）≠ 服务器上所有文件**

---

## 一、先建立最重要的认知

```
你通过浏览器/curl 访问的 = 服务器上【web 目录】(如 /var/www/html) 里的文件
服务器上【所有文件】    = 整个磁盘（根目录 /、/etc、/flag、/home...）
                              ↓ 这些 web 目录之外的文件，浏览器访问不到！
```

**为什么 flag 常放在 web 目录外？**
出题人把 flag 放在根目录 `/flag`（web 目录之外），这样：
- 你直接访问 `http://靶机/flag` → ❌ 访问不到（web 服务器只服务 web 目录）
- 必须靠漏洞（RCE、任意文件读取、目录穿越）才能把它"捞"出来

> 这就是为什么上一题：**扫目录发现不了真 flag，得用 PHP 执行器去读 `/flag`**。

## 二、目录扫描的原理（scanner 是怎么工作的）

### 核心逻辑：逐个请求，看返回码
```
scanner = 拿一本"常见文件名词典"(wordlist)，挨个试访问：
   http://靶机/robots.txt
   http://靶机/index.php.bak
   http://靶机/flag.txt
   http://靶机/.git/HEAD
   ...
每个请求看服务器返回什么：
   404 = 文件不存在 → 忽略
   200 = 文件存在 → 记录 ★
   301/403 = 目录/特殊 → 留意
```

**它不聪明，就是"穷举"**——靠词表里的常见文件名，猜网站里可能藏了什么。

### 我写的 mini_scanner.py 完整流程
```
① 请求 http://靶机/  +  一个不存在的路径 /zzz__不存在__
   → 拿到"默认页内容"（假200的模板）
② 逐个请求词表里的每个路径
③ 每个响应：
   - 404 → 跳过
   - 内容 == 默认页 → 判定【假200】→ 过滤
   - 其他 → 记录为【真实发现】
④ 输出真实发现列表
```

## 三、★ 假 200（最重要的坑）

### 什么是假 200
**很多服务器对"不存在的路径"不返回 404，而是统一返回 200 + 首页**（或自定义页面）。

```
访问 http://靶机/flag.txt      → 200 (返回首页内容)
访问 http://靶机/zzz不存在     → 200 (返回首页内容)  ← 和上面一样！
访问 http://靶机/index.php     → 200 (返回首页内容)  ← 一样！
```

**后果**：scanner 会以为 `flag.txt`、`backup.zip`、`admin` 全都存在 → **刷屏误报**。

### 怎么识别假 200
```
铁律：看内容，别只看状态码！
  返回【首页/默认页】内容 = 假 200（文件不存在）
  返回【独特内容】      = 真存在

判断方法（工具自动做的）：
  先访问一个"肯定不存在"的路径，记下默认页内容
  然后每个结果和默认页对比：一样 = 假，不一样 = 真
```

### 假 200 常见场景
| 服务器类型 | 行为 |
|---|---|
| 单页应用(SPA)/Node | 所有路径返回 index.html |
| 配置了 fallback | 未知路径重定向/返回首页 |
| 某些 PHP/静态站 | 自定义 404 页面也返回 200 |

## 四、判断"真文件"的完整方法

```
① 看状态码：404 = 不存在；200 = 可能存在
② 看内容长度：
   和首页一样长/一样内容 → 假200
   长度不同/内容独特     → 可能是真的
③ 直接 curl 看内容：
   curl -s http://靶机/flag.txt
   返回 flag/源码/文件内容 → 真
   返回一坨 HTML 首页     → 假
④ 有些 200 是"需要认证才返回真内容" → 结合其他信息判断
```

---

## 五、目录扫描的局限（老实说）

1. **只能扫"web 目录里"的文件**——web 目录之外的 flag 永远扫不到（这就是为什么 RCE 必要）
2. **词表有限**——冷门文件名可能漏掉（所以有专门的大字典，如 dirsearch 的 db）
3. **假 200 会误导**——必须配合内容判断
4. 扫描 ≠ 一定找到——**但扫描 = 确定"没漏掉常见项"**

---

## 六、一句话总结

> **扫描器是"用词表穷举网站里可能存在的文件"，报 200 别全信，要看内容是不是首页；真正的 flag 经常在 web 目录之外，要靠 RCE 等漏洞去读。**
