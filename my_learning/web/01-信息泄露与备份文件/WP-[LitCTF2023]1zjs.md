# 【WriteUp】[LitCTF 2023] 1zjs ｜ NSSCTF 3871

> 日期：2026-08-01 ｜ 平台：NSSCTF ｜ 方向：Web / JS分析 ｜ 难度：☆ 但套路很新

## 考点
元素审查 → 脚本定位 → 脚本内注释线索 → JSFuck 混淆 → 执行字符串

## 完整解题链（按正确顺序）

### 第 1 步：审查元素（F12 / Ctrl+U）
打开靶机，审查元素（查看源代码），发现：
```html
<script src="./dist/index.umd.js"></script>
```
→ **定位到了 JS 脚本**，这是解题的入口。

### 第 2 步：下载并通读 JS（重点：看注释！）
下载 `dist/index.umd.js`，**不要只 grep flag，要通读，特别是注释**。
在 tslib 版权注释（一坨看着像"无关紧要的版权声明"）里发现出题人藏的话：

```
/*! ... Copyright (c) Microsoft Corporation. ...
    Your gift just take it : /f@k3f1ag.php
    ***************************************************************************** */
```

> 💡 出题人把线索埋在"看起来最无害"的地方——版权注释。因为没人会读它。

### 第 3 步：访问注释里给的路径
```
访问 http://靶机/f@k3f1ag.php
```
返回一坨全部由 `[ ] ( ) ! +` 组成的代码。

### 第 4 步：识别 JSFuck
代码里没有任何字母/数字，只有 6 种字符 → 这是 **JSFuck** 混淆。
JSFuck 是一种只用了 6 个字符（`[]()!+`）就能写出任意 JS 的编码方式。

### 第 5 步：执行字符串拿 flag
JSFuck 本身就是合法 JS，直接 eval 执行：
```js
// 浏览器 F12 → Console 粘贴回车，或：
node -e "console.log(eval(require('fs').readFileSync('jsffuck.txt','utf8')))"
```
执行结果：`NSSCTF{8d55061f-2f2d-40ed-a5dd-751a016d6c35}`

## 收获（新知识点）
1. **审查元素永远是 Web 题第一步** —— 看源码、找脚本、看注释
2. **JS 注释是"藏宝地"** —— 版权注释、冷门位置最容易藏线索，必须读
3. **JSFuck 识别特征**：全篇只有 `[]()!+` 六种字符 → 扔进 eval 执行
4. **文件名会骗人**：f@k3（fake）越说自己是假 flag，越可能是真线索

## 踩过的坑（老师自己犯的错）
- ❌ 只 grep "flag" 字符串、深挖 source map 和图片 → 绕远路
- ✅ 应该先通读 JS 看注释 → 线索就在那
- **教训：flag 不一定以字符串形式藏在代码里，线索常在注释/文件名/响应头等"边角料"**
