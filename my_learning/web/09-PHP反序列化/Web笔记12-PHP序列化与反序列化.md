# Web笔记12 - PHP 序列化与反序列化（小白啃透版）

> 目标：看一眼 `O:4:"test":2:{s:4:"user";...}` 这种乱码，能**逐字读懂**它是什么、为什么这么写。
> 配套：上一题 `http://challenge.qsnctf.com:40507/` 的反序列化绕过题。
> 下面每个例子都是 **「PHP 源码 → 序列化结果 → 逐字段对照表」** 三段式，所见即所得。

---

## 一、为什么要序列化？（先有体感）

程序运行时，数组、对象都活在**内存**里。内存里的东西没法直接发网络、存文件。

- **序列化 `serialize()`** = 把内存里的数据结构"压扁"成一段字符串
- **反序列化 `unserialize()`** = 把这段字符串"吹胀"回原来的数据结构

> 🏢 比喻（和上一题一致）：对象 = 大楼；序列化串 = 装箱清单；反序列化 = 照清单还原大楼。清单写"密码=escaping"，还原出来的大楼密码就真是 escaping。

---

## 二、总规律一张表（先把骨架记住）

每种类型都用**一个字母开头**标明"我是谁"，再跟长度/个数，用 `:` 分隔，用 `;` 或 `}` 收尾。括号像**俄罗斯套娃**层层嵌套。

| 类型 | 标记 | 写法模板 |
|---|---|---|
| 字符串 string | `s` | `s:长度:"值";` |
| 整数 int | `i` | `i:数字;` |
| 浮点 float | `d` | `d:数字;` |
| 布尔 bool | `b` | `b:1;`(真) / `b:0;`(假) |
| 空 NULL | `N` | `N;` |
| 数组 array | `a` | `a:个数:{键值对...}` |
| 对象 object | `O` | `O:类名长:"类名":属性数:{...}` |

---

## 三、基础类型：调用 → 结果 对照

左边是 `serialize(某值)` 的输入，右边是吐出来的字符串。

| PHP 调用 | 序列化结果 | 拆解 |
|---|---|---|
| `serialize("hello")` | `s:5:"hello";` | 字符串，5 个字符 |
| `serialize(18)` | `i:18;` | 整数，无引号 |
| `serialize(3.14)` | `d:3.14;` | 浮点 |
| `serialize(true)` | `b:1;` | 布尔真 |
| `serialize(false)` | `b:0;` | 布尔假 |
| `serialize(NULL)` | `N;` | 空，只有 `N;` |

## 四、数组：某个数组 → 变成某个字符串（重点对照）

### 例子 A：关联数组

**PHP 源码**
```php
$arr = [
    "name" => "bob",
    "age"  => 18
];
echo serialize($arr);
```

**↓ 序列化结果**
```
a:2:{s:4:"name";s:3:"bob";s:3:"age";i:18;}
```

**↓ 逐字段对照表**

| 源码里的东西 | 序列化写法 | 说明 |
|---|---|---|
| 整个数组（2 个元素） | `a:2:{ ... }` | `a`=数组，`2`=元素个数 |
| 键 `"name"`（字符串） | `s:4:"name";` | 键也要序列化！4 个字符 |
| 值 `"bob"`（字符串） | `s:3:"bob";` | 3 个字符 |
| 键 `"age"`（字符串） | `s:3:"age";` | 3 个字符 |
| 值 `18`（整数） | `i:18;` | 整数用 `i:`，**没有引号** |

> ⚠️ 关键认知：**数组的"键"本身也要序列化**。字符串键用 `s:`，整数索引键用 `i:`（见下例）。

### 例子 B：索引数组（没有键名，只有 0/1/2）

**PHP 源码**
```php
$list = ["a", "b", "c"];
echo serialize($list);
```

**↓ 序列化结果**
```
a:3:{i:0;s:1:"a";i:1;s:1:"b";i:2;s:1:"c";}
```

**↓ 逐字段对照表**

| 源码里的东西 | 序列化写法 | 说明 |
|---|---|---|
| 整个数组（3 个元素） | `a:3:{ ... }` | 3 个元素 |
| 第 0 个：键 `0` / 值 `"a"` | `i:0;s:1:"a";` | 索引键用 `i:0;`，值 `"a"` 是 1 字符 |
| 第 1 个：键 `1` / 值 `"b"` | `i:1;s:1:"b";` | 同上 |
| 第 2 个：键 `2` / 值 `"c"` | `i:2;s:1:"c";` | 同上 |

## 五、对象：某个对象 → 变成某个字符串（重点对照）

### 例子 C：一个 `User` 对象（public 属性）

**PHP 源码**
```php
class User {
    public $name = "bob";
    public $age  = 18;
}
$u = new User();      // 实例化，name=bob, age=18
echo serialize($u);
```

**↓ 序列化结果**
```
O:4:"User":2:{s:4:"name";s:3:"bob";s:3:"age";i:18;}
```

**↓ 逐字段对照表**

| 源码里的东西 | 序列化写法 | 说明 |
|---|---|---|
| `class User`（类名 4 字母） | `O:4:"User"` | `O`=对象，`4`=类名长度 |
| 共 2 个属性 | `:2:` | 属性个数 |
| 属性 `name = "bob"` | `s:4:"name";s:3:"bob";` | 属性名是字符串，值也是字符串 |
| 属性 `age = 18` | `s:3:"age";i:18;` | 属性名字符串，值整数 |

👉 **对象 vs 数组的唯一区别**：对象在 `a:` 的位置换成了 `O:类名长:"类名":`，其余属性写法和数组一模一样。

---

## 六、⚠️ 最易踩的坑：public / protected / private（对照）

属性前面的关键词会改变序列化后**属性名的写法**。下面三个小例子一一对照。

### 例子 D：protected 属性

**PHP 源码**
```php
class User {
    protected $pass = "x";
}
$u = new User();
echo serialize($u);
```

**↓ 序列化结果**
```
O:4:"User":1:{s:7:"\x00*\x00pass";s:1:"x";}
```

**↓ 逐字段对照表**

| 源码 | 序列化写法 | 说明 |
|---|---|---|
| 类名 `User` | `O:4:"User"` | 4 字母 |
| 1 个属性 | `:1:` | |
| 属性名 `pass`（protected） | `s:7:"\x00*\x00pass";` | 被塞进**两个看不见的 `\x00`** + 中间一个 `*`，长度 = 1+1+1+4 = **7** |
| 值 `"x"` | `s:1:"x";` | 1 字符 |

### 例子 E：private 属性

**PHP 源码**
```php
class User {
    private $secret = "y";
}
$u = new User();
echo serialize($u);
```

**↓ 序列化结果**
```
O:4:"User":1:{s:12:"\x00User\x00secret";s:1:"y";}
```

**↓ 逐字段对照表**

| 源码 | 序列化写法 | 说明 |
|---|---|---|
| 类名 `User` | `O:4:"User"` | 4 字母 |
| 1 个属性 | `:1:` | |
| 属性名 `secret`（private） | `s:12:"\x00User\x00secret";` | 格式 = `\x00` + 类名 + `\x00` + 属性名，长度 = 1+4+1+6 = **12** |
| 值 `"y"` | `s:1:"y";` | 1 字符 |

> 💡 **为什么重要**：CTF 题常让你构造带 `private` 属性的对象。那些 `\x00` 在终端/网页里**显示为空格或根本看不见**，但**字节数一个都不能少**，少了 `unserialize` 就报错失败。构造时务必精确数长度、补上 `\x00`。

## 七、反序列化：字符串怎么变回对象（危险的根源）

`unserialize($str)` 按格式解析还原成对象。**最致命的一点**：

> 🔥 **还原出来的对象，属性值完全由这段字符串决定，跟源码里写的默认值无关！**

```php
class test {
    var $pswd = 'sunshine';     // 源码默认值是 sunshine
}
// 但我们反序列化的是下面这段：
$o = unserialize('O:4:"test":1:{s:4:"pswd";s:8:"escaping";}');
echo $o->pswd;   // 输出 escaping，不是 sunshine！
```

这就是**属性覆盖**，也是上一道题能拿到 flag 的根本原因。

---

## 八、反序列化为什么危险？（小白先留个轮廓）

光 `unserialize` 不可怕，可怕的是它**会悄悄自动触发某些"魔法方法"**：

| 魔法方法 | 什么时候自动触发 |
|---|---|
| `__wakeup()` | 反序列化**一完成**就调用 |
| `__destruct()` | 对象被销毁（脚本结束）时调用 |
| `__toString()` | 对象被当成字符串打印时调用 |

如果魔法方法内部调用了危险函数（`system()`、`eval()`、`file_get_contents()`…），攻击者就能通过精心构造的对象"**借刀杀人**"。进阶玩法叫 **POP 链**，先留印象，以后开专题。

## 九、回头啃那道题的 payload（收口）

上一题我们发的：
```
O:4:"test":2:{s:4:"user";s:4:"test";s:4:"pswd";s:8:"escaping";}
```

对照表：

| 含义 | 序列化写法 |
|---|---|
| `test` 类的对象 | `O:4:"test"` |
| 2 个属性 | `:2:` |
| `user = "test"` | `s:4:"user";s:4:"test";` |
| `pswd = "escaping"`（覆盖默认 sunshine） | `s:4:"pswd";s:8:"escaping";` |

还原后 `$profile->pswd == 'escaping'` 成立 → 打印 flag。全程没出现 `flag`/`php` → 逃过黑名单。✅

## 十、速查口诀（背下来）

1. 类型字母：**s** 串 **i** 数 **d** 浮 **b** 布尔 **N** 空 **a** 数组 **O** 对象
2. 写法模板：`类型:长度:"值";`（数组/对象是 `类型:个数:{...}`）
3. 对象比数组多"类名"：`O:类名长:"类名":属性数:{...}`
4. 数组/对象的**键**也要序列化（字符串键 `s:`、整数键 `i:`）
5. **属性值由字符串决定** —— unserialize 能覆盖源码默认值（属性覆盖）
6. `private`/`protected` 属性名带不可见 `\x00`，长度要数准
7. 危险在魔法方法（`__wakeup`/`__destruct`/`__toString`）自动触发
