# 🕸️ 12 · SSRF（服务器端请求伪造）

## 一、题型概述

服务器替你发请求并把结果回显 → 用它访问**只有服务器能访问**的地方（本机/内网/云元数据），是打内网、读内部接口的利器。

## 二、常考考点

- **识别 SSRF**：提交一个 URL，页面回显"状态码 + 响应头 + 响应体" → 后端真去请求了。
- **黑名单测绘（核心方法）**：用「**秒拒 vs 超时**」二分——秒拒=请求被拦（没发出）；超时=请求发出去了但目标无服务（**没被拦**）。瞬间反推黑名单范围。
- **回环绕过**：黑名单只拦 `127.0.0.1` → 用 **Docker 网关 `172.17.0.1:端口`** 访问服务器自身（gunicorn 监听 `0.0.0.0`，经端口映射可达）。
- **内网横向**：扫同网段 `172.17.0.x` / `10.x` / `192.168.x` 找第二个容器/服务。
- **302 跟随**：后端跟随重定向且不复检 → 公网 302 跳内网。
- **协议黑名单**：`file://`/`dict://`/`gopher://` 常被拦，看放行哪些。

## 三、解决方法 / 通用套路

1. 喂 `http://example.com` 验证 SSRF + 看回显结构。
2. **测绘黑名单**：用秒拒/超时二分，弄清拦了什么（IP 段？协议？）。
3. 内网 IP 被拦 → 试 **`172.17.0.1` 网关**、十进制/十六进制 IP、域名等绕过。
4. 自身通道打通后，**枚举内部路由 / 扫同网段端口**找藏 flag 的服务。
